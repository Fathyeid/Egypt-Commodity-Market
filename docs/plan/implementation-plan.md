# خطة التنفيذ: منصة تعلم اللغات بالذكاء الاصطناعي

> **تحديث (19 نوفمبر 2026): تغيير البنية بقرار صاحب المشروع**
> استبعدنا Supabase لأن الحساب وصل لحد المشروعات المجانية. البديل المعتمد:
> - **قاعدة البيانات:** PostgreSQL عادية عبر Drizzle ORM. تعمل على أي استضافة: محلياً، أو Neon أو Railway المجانيتين، أو سيرفر خاص.
> - **تسجيل الدخول:** better-auth، ويدعم البريد وكلمة المرور، وGoogle، واستعادة كلمة المرور.
> - **الحماية:** طبقة وصول للبيانات تفلتر كل استعلام بمعرّف المستخدم، بدل RLS في Supabase. عليها اختبارات آلية تثبت عزل بيانات كل مستخدم.
> - **تخزين الملفات والصوتيات (المرحلة 4):** سيُختار لاحقاً، مثل Cloudflare R2 أو أي خدمة متوافقة مع S3.
>
> كل ما يذكر Supabase في الأقسام التالية يُقرأ على هذا الأساس.

> **الاسم المؤقت:** Lisan / لسان.
> هذا اسم عمل فقط. يجب التحقق من توفر العلامة التجارية والنطاق قبل اعتماده.

## 1. المبادئ الحاكمة

1. **لا بيانات وهمية تُعرض على أنها حقيقية.**
   - كل رقم في لوحة المتعلم يأتي من قاعدة البيانات.
   - الشاشات التجريبية تحمل شارة "بيانات عرض".
2. **أي خدمة غير مفعلة تظهر بحالتها الحقيقية.** نظهر للمستخدم "غير مفعّل بعد" ولا نتظاهر بأن الخدمة تعمل.
3. **لا مفاتيح API في الواجهة الأمامية.** كل نداء لخدمة ذكاء اصطناعي أو صوت أو دفع يمر عبر الخادم (Route Handlers أو Supabase Edge Functions).
4. **لا تفعيل لأي خدمة مدفوعة دون موافقة صاحب المشروع.** يشمل ذلك LLM وSTT وTTS وتقييم النطق والدفع.
5. **ملف المتعلم (Learner Model) هو القلب:** كل نشاط يكتب فيه، وكل ميزة تقرأ منه.
6. **مرحلة واحدة في كل مرة:** لا ننتقل لمرحلة جديدة قبل اجتياز معايير قبول المرحلة الحالية.

## 2. البنية التقنية

```
┌──────────── Next.js (App Router, TypeScript) ────────────┐
│  UI: Tailwind + Radix primitives, next-intl (ar RTL/en LTR) │
│  PWA (offline lessons/SRS)                                 │
│  Server: Route Handlers / Server Actions  ← المفاتيح هنا فقط │
└──────────────┬──────────────────────────────┬─────────────┘
               │                              │
        Supabase                       Provider adapters (قابلة للتبديل)
  ┌──────────────────────┐        ┌────────────────────────────────┐
  │ Postgres + RLS        │        │ LLMProvider   (Claude / غيره)   │
  │ Auth (Email, Google)  │        │ STTProvider   (Azure / Whisper…)│
  │ Storage (audio/media) │        │ TTSProvider   (Azure / …)       │
  │ Edge Functions / Cron │        │ PronunciationProvider (Azure)   │
  └──────────────────────┘        │ PaymentProvider (Stripe/Paymob) │
                                  └────────────────────────────────┘
```

**طبقة المحولات (Adapters):**
- كل خدمة خارجية خلف واجهة TypeScript موحدة.
- عندما لا يوجد مفتاح، يرجع المحول الحالة `{ status: "not_configured" }`. الواجهة تعرض هذه الحالة بوضوح بدل أن تفشل بصمت أو تزيّف النتيجة.

**إضافة لغة جديدة دون إعادة بناء:**
- اللغات صفوف في جدول `languages` ومعها:
  - `script` (نظام الكتابة).
  - `direction` (اتجاه الكتابة).
  - رموز الخدمات الصوتية (`stt_locale`، `tts_voice`، `pron_assessment_supported`).
  - المناهج.
- المحتوى بيانات، وليس كوداً.

## 4. الخدمات الخارجية المقترحة (كلها تحتاج موافقتك)

| الخدمة | الاقتراح | السبب | البديل |
|---|---|---|---|
| قاعدة البيانات والمصادقة والتخزين | Supabase | مطلوب في المواصفات | — |
| تسجيل الدخول بحساب Google | Google OAuth عبر Supabase | مطلوب | — |
| نموذج لغوي (المدرس والمحادثة والتصحيح) | Claude (Anthropic API) عبر المحول | جودة عالية في التصحيح والشرح متعدد اللغات | أي نموذج آخر عبر نفس الواجهة |
| تحويل الكلام إلى نص + تقييم النطق | Azure AI Speech (Pronunciation Assessment) | تقييم حقيقي على مستوى الكلمة والصوت، ويدعم عدة لغات | Speechace (إنجليزي أساساً) |
| تحويل النص إلى كلام | Azure Neural TTS | أصوات للغات الـ 12 كلها | ElevenLabs، Google TTS |
| الدفع | Stripe (عالمي) + Paymob أو Fawry (مصر/المنطقة) | حسب الدولة | Paddle |

**تنبيه عن النطق:**
- تقييم الإيقاع والتنغيم (Prosody) كان موثقاً في Azure للغة en-US فقط.
- بقية اللغات لها مستويات دعم مختلفة.
- سنعرض لكل لغة بطاقة "ما نقيسه وما لا نقيسه" تُبنى من جدول `languages`.

## 5. المراحل ومعايير القبول

### المرحلة 1: الهوية والواجهة والتسجيل والملف الشخصي واختيار اللغة

**ما نبنيه:**
- هوية بصرية: نظام ألوان وخطوط ومكونات، مع الوضع الفاتح والداكن، والعربية (RTL) والإنجليزية (LTR).
- الصفحة الرئيسية التسويقية.
- التسجيل وتسجيل الدخول:
  - البريد الإلكتروني وكلمة المرور.
  - رابط سحري.
  - Google.
  - استعادة كلمة المرور.
- معالج البداية (Onboarding):
  - اللغة الأم.
  - اللغة المستهدفة (12 لغة).
  - الهدف.
  - الوقت اليومي.
  - المستوى الذاتي.
- صفحة الملف الشخصي وإدارة المسارات (أكثر من لغة لكل مستخدم).
- لوحة المتعلم بهيكلها الأولي:
  - تعرض الأرقام الحقيقية فقط.
  - في البداية تكون الأرقام صفراً، مع دعوة لبدء اختبار تحديد المستوى.

**معايير القبول:**
**حالة معايير القبول (19 نوفمبر 2026):**
- [x] مستخدم جديد يسجل بالبريد، ويكمل المعالج، ويجد بياناته بعد الدخول من جلسة متصفح جديدة. يغطي ذلك اختبار E2E.

### المرحلة 2: اختبار تحديد المستوى والمناهج والدروس والتمارين

**ما نبنيه:**
- اختبار تحديد مستوى تكيّفي (Computerized Adaptive Test) لأربع مهارات: المفردات والقواعد والقراءة والاستماع.
  - يعتمد على بنك أسئلة موسوم بمستوى CEFR.
  - يتوقف عند استقرار التقدير.
- الكتابة والمحادثة والنطق:
  - تُقيَّم في المرحلتين 3 و4 بعد تفعيل الخدمات.
  - قبل التفعيل تظهر هذه الأجزاء بحالة "يتطلب تفعيل الخدمة".
- تقرير المستوى: لكل مهارة على حدة، مع خطة أولية.
- محرك الدروس:
  - الأقسام الثمانية لكل درس.
  - 8 أو أكثر من أنواع التمارين: اختيار، وملء فراغ، وترتيب، ومطابقة، وإملاء، وكتابة قصيرة، وتحدث، واستماع.
- محتوى أولي: مستوى A1 كامل للغتين (الإنجليزية والألمانية للمتحدث بالعربية) لإثبات النموذج. بعدها نتوسع.

> **ملاحظة:** إنتاج محتوى تعليمي جيد لـ 12 لغة و6 مستويات عمل تحريري ضخم. الخطة:
> 1. يولّد الذكاء الاصطناعي مسودات منظمة.
> 2. يراجعها محرر بشري في لوحة الإدارة.
> 3. تُعتمد للنشر.
>
> لن ننشر محتوى غير مراجع على أنه منهج نهائي.

### المرحلة 4: النطق والاستماع والكتابة

- **مدرب النطق:**

- **مركز الاستماع:**

- **أكاديمية القراءة والكتابة:**
  - قصص ومقالات حسب المستوى، مع أسئلة فهم.
  - مساعد كتابة يعطي نسخة محسنة ويشرح الأخطاء.

## 6. الخطة التكيفية (منطق مبدئي)

```
كل ليلة (أو بعد كل جلسة):
  weakness[skill] = target_level - current_level  (من skill_levels)
  frequent_errors = top grammar_tags في error_log آخر 14 يوم (مرجّحة بالحداثة)
  due_vocab      = user_vocab حيث due <= now

خطة اليوم (بقدر daily_minutes):
  20–40% مراجعة SRS مستحقة
  30–50% أنشطة للمهارة الأضعف (القراءة جيدة والمحادثة ضعيفة ← Roleplay/نطق)
  10–20% تمارين علاجية مولدة لأكثر grammar_tag تكراراً (مثلاً الماضي البسيط)
  الباقي: الدرس التالي في المنهج
```

## 7. ما أحتاجه منك قبل بدء المرحلة الأولى

1. **المستودع:** المستودع الحالي اسمه `egypt-commodity-market` وهو فارغ.
   - هل نبني المنصة داخله؟
   - أم تفضل إنشاء مستودع جديد باسم المشروع وتضيفه للجلسة؟
2. **الاسم والهوية:** هل نعتمد اسم "لسان / Lisan" كاسم عمل، أم لديك اسم؟
3. **Supabase:**
   - هل أنشئ مشروعاً جديداً على حسابك المتصل؟
   - إنشاء المشروع قد يترتب عليه تكلفة حسب خطتك، لذلك لن أنشئه قبل موافقتك.
4. **Google OAuth:** يحتاج إنشاء OAuth Client من Google Cloud Console على حسابك. سأعطيك الخطوات بالتفصيل.
5. **الموافقة على التصميم الأولي** في `design/prototype.html`.
